9-Blocker justification (D2 / F3):
D2 — Structured/textual input with high reliability: Telemetry (kW/kWh/price numbers) + textual weather/storm alerts; reliability enforced by hard constraints in the LP (min SOC, critical-load penalties, capacity caps), plus a greedy fallback solver and an agentic replan loop that bumps reliability when the first plan is unsafe. Validator ensures zero unmet critical load across all tested scenarios.

F1 — Optimal cluster of actions: LP produces charge/discharge/buy/sell/curtail/DR decisions across all assets each tick.F1
F2 — Optimality criteria adjusted per situation + uncertainty: Agent dynamically selects 6 objective weights (high price → profit+reliability, surplus RE → curtailment+carbon, storm → reliability+reserve, off-peak → cost+battery-life), explicitly reasons about forecast confidence, and holds battery reserve proportional to uncertainty.F2
F3 — Simulation over time with varying conditions: Continuous 24-hour simulation with stochastic weather, price volatility, forecast errors, and live event injection (battery faults, line trips, storms, price spikes/demand surges). Pre-built scenarios (Summer Peak, Stormy Night, Price Volatility, Normal Day) demonstrate robust adaptability.F3

Responsible AI / robustness: Structured JSON outputs with clamping · Deterministic fallback on LLM failure · LP hard constraints (physics cannot be violated) · Human override panel · Full audit trail (state + reasoning saved every tick).
Scalability: Assets are configuration-driven; adding farms/BESS/consumers is a data change, not a code change.
